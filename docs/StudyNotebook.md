# Study notebook

The notebook lives inside **Profile → Your videos → Saved**, alongside the existing playlists.
Choose **Study notebook** from a video's bookmark menu to add it. Use the pencil beside its title
to write your own study notes. Playlists continue to organize videos independently.

## Features

- Keep up to 500 videos in the notebook.
- Add, edit and clear a personal note of up to 2,000 characters for each notebook video.
- Save explicitly with **Save note** or **Ctrl+Enter**. Failed requests retain the current draft.
- Search titles, creators and saved note text. Filter videos with or without notes.
- Download all saved notes as a plain text file containing titles, creators and YouTube links.
- An unsaved draft prompts before closing the editor or navigating away. Filtering the list keeps
  the open editor and its draft available. Browser reloads use the browser's unsaved-changes prompt.
- Removing a notebook video removes its saved note after confirmation. Playlist copies stay saved.

## Files and data flow

| File | Responsibility |
| --- | --- |
| `frontend/src/components/StudyNotebook.tsx` | Search controls, filters, video actions, note editor and feedback |
| `frontend/src/lib/studyNotebook.ts` | Search/filter logic and plain text export |
| `frontend/src/api/savedVideos.ts` | Adds, removes and lists notebook videos |
| `frontend/src/api/studyNotes.ts` | Calls the backend through the existing shared request helper |
| `frontend/src/pages/YourVideosPage.tsx` | Embeds the notebook in the existing Saved tab and protects unfinished drafts |
| `backend/.../saved/SavedVideoController.java` | Session checks and video id validation for notebook videos |
| `backend/.../saved/SavedVideoRepository.java` | Owner-scoped SQL and the 500-video limit |
| `backend/.../migration/V10__saved_videos.sql` | The notebook's video list |
| `backend/.../saved/StudyNoteController.java` | Session checks, strict JSON validation and note endpoints |
| `backend/.../saved/StudyNoteRepository.java` | Parameterized, owner-scoped SQL |
| `backend/.../migration/V11__study_notes.sql` | Adds note storage linked to existing saved-video entries |

The editor sends `{ "note": "your text" }` with `PUT /api/me/study-notes/{youtubeId}`. The backend
takes the user id from the session and updates only that user's notebook entry. `GET
/api/me/study-notes` returns that user's notes. An empty note clears the text and keeps the video.
Notes are stored in PostgreSQL; they are not kept in localStorage or generated by an AI.

The new migration is additive. Keep previously applied migration files unchanged. Coordinate the
next migration number with the team before merging if main gains another V11 in the meantime.

## Validation

From the repository root, run these separately:

```powershell
docker compose run --rm backend-tests
docker compose exec frontend npm test -- --no-file-parallelism
docker compose exec frontend npm run build
docker compose up -d --build backend
docker compose logs --tail=60 backend
```

The backend restart applies V11 automatically. Do not reset the database volume for this feature.
Controller tests make real HTTP/JSON requests against a repository test double. They test login
requirements, input rules and controller ownership behavior; they do not test live PostgreSQL.

Verify the complete flow in the running app:

1. Save two videos to the Study notebook. Keep one in Watch later as well.
2. Open Your videos → Saved and use the pencil on a notebook video.
3. Write a unique note, save it, refresh, and confirm it is restored.
4. Search for a word found only in that note. Try both note filters.
5. Download notes and open the text file. Confirm the title, creator, link and saved text.
6. Edit a note and cancel leaving the editor. Confirm the draft is retained.
7. Sign out and sign in to a second account. Confirm the first account's note is absent.
8. Save the same video in the second account and write a different note. Switch accounts and
   confirm each account retains its own note.
9. Clear a note and confirm the video stays saved. Remove a notebook video and confirm its
   separate Watch later/playlist copy stays saved.
10. Narrow the browser to phone width. The toolbar should stack, the editor should fit, and
    table scrolling should remain inside its container.
